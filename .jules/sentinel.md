## 2025-05-24 - Case-Insensitive URL-Encoded Secret Redaction
**Vulnerability:** The error message sanitizer `_sanitize_error_msg` performed a strict, case-sensitive `.replace()` when redacting URL-encoded API keys. Because percent-encoding can validly use both lowercase and uppercase hex characters (e.g., `%3a` vs `%3A`), external services reflecting these secrets could easily bypass the redaction logic.
**Learning:** Hardcoded, case-sensitive string replacement is insufficient for normalized data formats like URL encoding. Different libraries and API gateways encode/decode characters with varying casing conventions.
**Prevention:** Always use case-insensitive matching (e.g., `re.sub(..., flags=re.IGNORECASE)`) for URL-encoded variations of credentials when implementing output sanitization or log redacting logic.
